# D376 - AccessKit adapters for the native lyric-ui host (lyric-access)

**Status:** accepted; implemented (docs/67 phase G10, #8489, completing the AccessKit half of #8430). Extends D214.

## Decision

1. **AccessKit through its C API, bound by `lyric bindgen`.** `lyric-access/platform/` binds accesskit-c 0.23.2 as `Access.Kernel.Accesskit`, generated from `<accesskit.h>` with the allow-list in `platform/native/` and never edited by hand. Each platform has its own adapter functions, so the kernel is generated once per OS (`accesskit_linux.l`, `accesskit_macos.l`, `accesskit_windows.l`, each `@cfg(target_os = ...)`), from one allow-list that names adapter functions by pattern. `lyric restore` fetches the release archive (pinned by SHA-256) for Linux x86-64, macOS (arm64 and x86-64) and Windows x86-64, whose shared library ships beside the program; other targets (Linux arm64) find a source build through `pkg_config = "accesskit"`, which `scripts/ci/build-accesskit.sh --source` makes from the tagged source, verified by commit.
2. **Planning is host-free.** `Access.Plan` (`lyric-access/`, every target) turns a `Ui.Native.Access` tree into what AccessKit takes: 64-bit node numbers (`Numbering`: given on first sight, kept while the id is in the tree, dropped when it leaves, never reused, so a request for a node that has gone resolves to nothing), one text-run node per line of an input's value (the break ends its line, character lengths in UTF-8), the selection's code point offsets moved onto runs, and the subset of the whole plan an update needs. A password input has no runs, as it publishes no value.
3. **The adapter is thin and thread-aware.** `Access.Platform.attach(window, title, scale)` creates the AT-SPI adapter on Linux, the NSAccessibility subclassing adapter on macOS and the UI Automation subclassing adapter on Windows (before the window is first shown, which UI Automation requires). `publish(adapter, tree)` diffs against the last tree, plans, keeps the whole plan for an assistive technology that connects later, and sends the changed nodes through `update_if_active`. AccessKit's activation and action callbacks can run on another thread (AT-SPI's), so they only read the kept plan and push requests, both through a protected type; the action request, a C union that bindgen does not bind, is read at offsets that `platform/native/accesskit_layout_check.c` checks against the header. Node bounds are the host's logical pixels times the window's pixel density; a label's text is its value, as AccessKit reads it.
4. **Requests use the input paths.** `takeRequests` maps AccessKit's focus, click, set-value and scroll-into-view actions back to host ids, and `Ui.Native.Run` carries each out through `Ui.Native.Access.resolveRequest` and the same functions the pointer and keyboard use (`focusBox`, a click at the box's centre, `applyEdit` over a full selection, page scrolling). The host publishes after every frame, reports window focus and, on X11, the window's position and decorations (`Window.windowBounds`, new `WindowMoved`/`WindowFocusGained`/`WindowFocusLost` events) so AT-SPI gives screen coordinates. The headless host exposes `accessTree` and `accessRequest`, so the scripted `--check` run drives the same request path on every native lane.
5. **Two tree fixes found by reading it over AT-SPI.** A link that navigates by `href` (no click event) now offers the click action (a host click, as a pointer click); a data grid cell, which layout wraps around the cell element at the same path, is one cell node instead of two nested ones.

## Verification

Linux: `scripts/ci/ui-native-e2e.sh` checks the generated kernel and the request layout against the header, runs the `Access.Plan` tests, the headless request scenario and the lyric-access smoke program, then runs the customers example in a D-Bus session with the AT-SPI bus enabled while `scripts/ci/atspi-smoke.py` reads the tree (roles, names, a table, a heading), clicks a customer link by its action, reads the name entry's text through the text runs, grabs focus and sets the text through EditableText. Windows: `scripts/ci/access-platform-e2e.sh` checks the Windows kernel and layout against the Windows headers and runs the smoke program while `scripts/ci/uia-smoke.ps1` invokes its button through UI Automation. macOS: the same script checks the macOS kernel and layout and attaches the NSAccessibility adapter to a Cocoa window; no client reads the tree, because a hosted runner grants no Accessibility permission (#8799, which also holds docs/67 G10's VoiceOver exit criterion).
