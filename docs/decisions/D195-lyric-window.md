# D195 - `lyric-window`: windows, input, clipboard, timing and audio over SDL3

**Status:** accepted, implemented for `--target native` (docs/67 phase G4, #7943); builds on D188 to D194

## Decision

1. **Layering.** `Window.Kernel.Sdl` is generated by `lyric bindgen` from `<SDL3/SDL.h>` with an
   allow-list (init, windows, events, clipboard, timing, audio streams) and never edited by hand;
   CI regenerates it with `--check`. `Window` is the safe layer: no `NativePtr` in its public API,
   a window is a record around an opaque handle.
2. **SDL3 discovery.** `[native.libs.SDL3] pkg_config = "sdl3"`, version 3.2.0 or later. A
   developer uses the distribution's SDL3; CI builds the pinned `libsdl.org` 3.4.18 release
   tarball (SHA-256 in `scripts/ci/build-sdl3.sh`) with the console-build flag, so it needs no
   window-system or sound-server packages. SDL3 has no prebuilt Linux archive to pin, which is
   why this is `pkg_config` and not a `prebuilt` table.
3. **Events.** `SDL_Event` is a union, which bindgen binds as `NativePtr[Byte]`; `Window` decodes
   the 128-byte buffer into a Lyric `Event` union (`Quit`, `WindowCloseRequested`,
   `WindowResized`, `KeyDown`/`KeyUp`, `TextInput`, `MouseMotion`, `MouseButtonDown`/`Up`,
   `MouseWheel`, `Other(kind)`). Every offset and flag constant the decoder spells out is
   compiled against SDL's headers by `lyric-window/native/sdl_layout_check.c`
   (`_Static_assert`s), so an SDL update that moves a field fails CI.
4. **Posting.** `post` queues key, mouse and quit events (SDL drops pushed window events, which
   belong to the window system; a text event carries a pointer), so input handling is testable
   without a display.
5. **Audio.** An `Audio` is a float-sample stream bound to the default playback device
   (`openAudio`, `queueSamples`, `queuedBytes`, `flushAudio`, `closeAudio`); no callback is used,
   so no closure outlives a call.
6. **GPU surface handles.** `nativeWindow` returns the X11, Wayland, Cocoa or Win32 handles from
   the window's SDL properties for `lyric-gpu`'s surface creation (`Unavailable` on the offscreen
   driver).
7. **Tests.** `lyric-window/examples/demo` runs in the `native-backend` job on SDL's `offscreen`
   video and `disk` audio drivers (`scripts/ci/window-examples-e2e.sh`): window creation and
   resize, posted key, mouse and quit events decoded back, the clipboard, timing, and a tone
   whose samples are read back from the disk driver's output file.

## Not in this slice

Gamepad, touch, IME composition events and file dialogs, a callback-based audio capture path,
window-resized and close events under a real window system (decoded from the documented offsets
but not produced by the offscreen driver), macOS in CI, and surface creation in `lyric-gpu`
(needs a window system; tracked in #8404 and the G4 follow-up issue).
