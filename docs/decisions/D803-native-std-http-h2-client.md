# D803 - Native `Std.Http` negotiates h2 through `H2Client`; the gRPC client builds on native (docs/72 slice 7)

**Status:** accepted. Implements the `Std.Http` half and the client half of slice 7 of `docs/72-h2-client-role-plan.md` (the "`Std.Http` integration" item of §3, §4.5). Builds on D800 (`Std.HttpEngine.H2Client`), D799 (client TLS and ALPN in `Std.TcpHost`), D802 (`Grpc.Client`) and D605 (token and deadline semantics of a native send). The native gRPC server is not in this decision: it is the portable server of slice 8.

## Decision

1. **ALPN `h2,http/1.1`.** An `https` connection of the native `Std.Http` kernel (`lyric-stdlib/std/_kernel_native/http_host.l`) offers `h2,http/1.1`, or only `http/1.1` when the client is pinned (`HttpVersion.Http11`, `hostClientWithTls`'s `pinHttp11`, the `*Http11` constructors). `HttpClientHandle` gained `allowH2`. A cleartext `http` URL stays HTTP/1.1 on every `Std.Http` target (no prior-knowledge h2c).
2. **One connection, either protocol.** When the handshake selects `h2` the connection is handed to the driver through the new `Std.HttpEngine.H2Client.h2ConnectOn(transport, opts)` (the tail of `h2Connect` extracted, additive; ownership of the transport passes to the driver, which closes it on failure). When the server selects `http/1.1` or nothing, the existing HTTP/1.1 client runs on that same connection: there is no second dial and no silent downgrade after a failed h2 attempt. One call per connection, closed afterwards, like the HTTP/1.1 path (no pooling; the header item stays).
3. **Request and response mapping.** The request becomes `:method`, `:scheme https`, `:path`, `:authority` (`Host` value), lowercased caller headers with the connection-specific ones dropped (`connection`, `keep-alive`, `proxy-connection`, `transfer-encoding`, `upgrade`, `host`, and a `te` other than `trailers`, RFC 9113 8.2.2), then `content-type` and `content-length` when there is a body; a list that still fails `isH2RequestHeaderListSafe` is an `Err` naming that. The response is buffered under the HTTP/1.1 path's caps (`maxResponseBodyBytes`, `maxHeaderCount`, `maxInterimResponses`, same messages); trailers are discarded; `hostResponseVersionMajor` answers 2 (`HttpResponseMessage.versionMajor`), so `HttpResponse.negotiatedVersion` is `Http2`. Redirects use the existing loop (a new connection per hop).
4. **D605 semantics over h2.** Connect and handshake are bounded by the token's deadline and wake pipe as before. The call carries the remaining time as its own deadline, rounded up so it never fires before the token's; the driver's reader enforces it within its 20 ms poll with RST_STREAM CANCEL; the write timeout is the time left. A failure while the token reads as cancelled is reported with the token's cause (`"request timed out"` for a deadline, `"request cancelled: cancellation was requested"` otherwise), so `HttpError.Timeout` and the cancelled cause are the same as on HTTP/1.1; anything else keeps its own message. `cancelSource` from another thread is noticed by a watcher task that checks the token every 5 ms and cancels the call: an h2 call blocks on the connection's mailbox, which a wake pipe cannot interrupt, and `Std.HttpServerHost` has no timed wait or condition (D800, OQ-7), so the bound is 5 ms, not "at once". A token that is already cancelled fails before any connection, as before.
5. **gRPC on native.** `lyric-grpc` gains a `native` feature and builds with `--no-default-features --features native`: the pure-Lyric client (`Grpc.Client`, `Grpc.Wire`, `Grpc.Types`, over `H2Client`) is the whole surface there. The server surface (`start`, `startHandle`, `startHandleAt`, `serverPort`, `stop`, `checkRateLimit`) and `Grpc.Aspects` are not built on native; `startHandle` carries `@cfg(not(feature = "native"))` and `server_tests.l` is gated the same way. The native server is the portable server of slice 8; those gates are removed there.

## Consequences for existing tests

A raw TLS peer that speaks HTTP/1.1 after the handshake is answered by the shared server's TLS context with ALPN `h2` when the client offers it. `http_timeout_native_tests.l`'s TLS client and the two `hostClientWithTls` clients of `llvm_http_client_self_test.l` (https cases) therefore pin HTTP/1.1; their subject is the HTTP/1.1 wire. New suites: `http_client_h2_native_tests.l` (10, the shared `Std.HttpServer` over TLS) and `http_client_h2_interop_tests.l` (4, `nghttpd` and `openssl s_server`, started by `scripts/ci/native-h2-client-interop.sh`).

## Deviations from docs/72

- Only the client half of the gRPC enablement. The plan's "client+server" needs a native-capable server; D287's server uses a dotnet monitor extern and the JVM's grpc-java `Server`, and slice 8 replaces both with one portable server, so building a native-only server here would be thrown away.
- The plan says the h2 path reuses `H2Client` "per `HttpVersion` semantics"; it is one connection per request, so `h2Connect`'s own dial is not used (`h2ConnectOn` is) and `H2ConnectAlpnNotH2` does not arise on this path.
- "Honours D605 token semantics" is met with a 5 ms cancel latency over h2 (item 4), documented in the kernel header.

## Findings recorded

- dotnet `Std.Http`: `client.send(request)` and `sendWithCancel` over TLS negotiate HTTP/1.1 against an h2 server where `client.get`/`post` negotiate h2 (the request's own `Version` overrides the client default). The JVM kernel negotiates h2 for both.
- JVM `Std.Http`: `sendWithCancel`'s `cancelSource` from another thread does not end a send waiting for the response (the send returns the late response); dotnet reports it as `HttpError.Timeout`.
