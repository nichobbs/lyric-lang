# D214 - The accessibility tree of the native lyric-ui host

**Status:** accepted; host-free half implemented (docs/67 phase G10, #8430). The AccessKit binding and platform adapters are #8489.

## Decision

1. **The tree is built host-free, from the laid-out boxes.** `Ui.Native.Access` (in `Lyric.Ui.Native.Core`, so it builds and is tested on every target) maps `Ui.Native.Layout` boxes to `AccessNode`s with the roles the web runtime gives the same widgets as ARIA: headings with levels, buttons, links, checkboxes with a checked state, text inputs, password inputs (value withheld), text areas (multiline), number inputs (spin button), selects (combo box with expanded state), tables and data grids (row and column counts, with `aria-rowcount` equal to the total rows plus the header row, `aria-rowindex` counted from the header as row 1, column headers with `aria-sort` and column indexes), dialogs (modal, named by their heading), banners and toasts as live regions (error and warning banners are alerts and assertive, the rest are polite status), and spinners as progress indicators.
2. **Labels and errors are the control's name and description.** A `field`'s label names its first control and its error messages are the control's description, with the invalid flag, as `runtime/ui.js` does with `aria-describedby`. Layout helper boxes (columns, rows, card bodies, dialog panels, a grid's scrolling body) produce no nodes.
3. **Ids are the host's.** Nodes use the host's stable id for a box (`idOfBox`, the keyed event path), with a path-derived fallback for boxes the host does not identify, so a keyed row keeps its id when rows around it move. The tree is a pre-order list of nodes with child id lists, the shape platform trees take.
4. **Updates are diffs.** `diffTrees` compares per-node signatures and returns the changed or new nodes, the removed ids and the focus, so an adapter sends only what moved.
5. **Requests from assistive technology reuse the input paths.** `resolveRequest` maps focus, click, set value and scroll into view to the same results the mouse and keyboard produce (`Interact.clickActions` for protocol events, a host click for selects and sortable headers, a text replacement for set value). A dialog is modal: nothing outside it resolves.
6. **AccessKit is not bound here.** The binding and the AT-SPI, UI Automation and NSAccessibility adapters need AccessKit built, which the environment this was written in could not do (crate and release downloads are blocked). Shipping an unverified binding was rejected; the remainder is #8489 with a concrete plan (`lyric-access` through `lyric bindgen`, the `Ui.Native.Run` wiring, an AT-SPI smoke test under Xvfb). The macOS VoiceOver smoke test still needs a macOS runner (#8401, #8419).
