# D194 - `lyric-gpu`: WebGPU compute and offscreen rendering over wgpu-native

**Status:** accepted, implemented for `--target native` (docs/67 phase G5, #7944; compute and offscreen render slice); builds on D188 to D193

## Decision

1. **Layering.** `Gpu.Kernel.Wgpu` is generated by `lyric bindgen` from wgpu-native's `webgpu.h`
   and `wgpu.h` (allow-list: every `wgpu*` and `WGPU*` name) and is never edited by hand; CI
   regenerates it with `--check`. `Gpu` is the safe layer: no `NativePtr` appears in its public
   API. Every GPU object is an opaque `Long` handle inside a record (`Device`, `Buffer`,
   `ComputePipeline`, `BindGroup`, `RenderTarget`, `RenderPipeline`).
2. **Library.** wgpu-native v29.0.1.1, restored from the pinned platform wheels of the `wgpu`
   0.32.0 release (the wheel's zip carries the shared library) through `[native.libs]` prebuilt
   archives (D191, D192). The Linux and macOS triples are pinned.
3. **Asynchrony.** Adapter, device and buffer-map requests use `AllowProcessEvents` callbacks
   that write into a `var`-field record the caller owns; the call then pumps
   `wgpuInstanceProcessEvents` and `wgpuDevicePoll` until the callback has run (bounded; timeout
   is an `Err`). The uncaptured-error callback keeps the first message of a burst in a C cell on
   the device, and the call that caused it returns it as `Err` (`takeError`).
4. **Data.** `buffer[Int]` and `buffer[Byte]` cross to the queue through `withPointer` and back
   through `withMutPointer`; pixels read from a target are repacked to tight RGBA8 rows.
5. **Pointer typing.** `NativePtr[Byte]` (C `void *`, and what `nativeNullPtr()` is) converts to
   any `NativePtr[T]`, and a `NativePtr[Record]` converts to `NativePtr[Byte]`. A pointer to a
   primitive or to another pointer does not convert to `NativePtr[Byte]`, so a mistyped buffer
   pointer is still T0043. A chained descriptor's `nextInChain` takes the first-member struct's
   address as a `NativePtr[Byte]`.
6. **Tests.** `lyric-gpu/examples/compute` (a WGSL pass doubles 1000 integers, all read back and
   checked) and `lyric-gpu/examples/triangle` (offscreen render compared to the checked-in golden
   image within a per-channel and a differing-pixel tolerance) run in the `native-backend`
   job on lavapipe (`scripts/ci/gpu-examples-e2e.sh`).

## Not in this slice

Textures with samplers and the textured-quad example, surfaces and presentation (need
`lyric-window`, G4, blocked on SDL3 binaries), vertex and index buffers, uniform buffers with
Float data (`buffer[Float]` writes), async pipeline creation, error scopes, and the JVM and
dotnet targets (the library is native-only, like `lyric-window`). Tracked in #8404.
