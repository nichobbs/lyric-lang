# D-progress-1042 — Generating NPM shims from `.d.ts`

**Status:** shipped (W5 follow-up, tracked in #8118 item 3)

`lyric restore --generate-npm-shims [--force]` writes `_extern_npm/<name>.l` from an
installed package's TypeScript declarations.

## Decision

1. **Which declarations.** Plain function declarations (`export function`,
   `export declare function`, `export default function`, `declare function` exported by
   `export { a as b }` or `export default name`, and an `export =` function as `default`)
   whose parameters and result are `string`, `number`, `boolean` or `bigint` (result also
   `void`). A `number` is a `Double`, never an `Int`, because that is what it is in
   JavaScript; the author narrows it by hand. Everything else (objects, classes, `const`
   function values, generics, overloads, optional, rest and destructured parameters,
   `Promise` results, namespaces) is written into the shim as `// skipped <name>: <why>`.
   `Promise` waits on the host-async work (#8118 item 1); a skipped overload is reported once.
2. **Where the declarations live.** `node` reads the package's `package.json`
   (`types`, `typings`, else `main` with `.d.ts`, else `index.d.ts`, else
   `@types/<name>`), so JSON is parsed by a real parser; the declaration file itself is
   scanned in Lyric. Only the one file is read: `export * from` and triple-slash
   references are not followed.
3. **Safe to rerun.** The output opens with the scaffold's `@axiom` header and a
   `// Generated by` marker. A restore replaces a missing shim, the plain scaffold, or an
   earlier generated file whose recorded content hash still matches (any edit, including an
   addition below the header, changes the hash); any other content is a hand edit and is left alone with a
   message unless `--force` is given. `--force` without `--generate-npm-shims` is an error.
4. **Names.** A JavaScript name that is a Lyric keyword gets a `_` suffix, other characters
   become `_`, and the default export is named for the package (`nodeFetch`); the import
   name stays the exact export, so the binding is unaffected. Two exports that map to the
   same name get further `_` suffixes.
5. **Checked by the build.** Every generated import is an export of the installed package,
   so the shim passes `B0062` as generated.
