# D795 - lyric-ws: the Autobahn nightly is not added yet, and permessage-deflate is out of scope (docs/73 slice S8, items iv and v)

**Status:** accepted. Resolves docs/73 question 7; leaves item (iv) of S8 open with its blockers recorded.

## Decision

1. **permessage-deflate (RFC 7692) is not implemented, and the server refuses to negotiate it.** docs/73 question 7 recommends unsupported, for the reasons that still hold: neither the Undertow kernel nor the pure-Lyric one ever supported it, nothing in the repository's own clients asks for it, and doing it properly needs a streaming raw DEFLATE with context takeover and a no-context-takeover mode from `Std.Zip` (D248's `Std.Zip` has whole-buffer DEFLATE and inflate; a streaming form is not there). The handshake never answers a `Sec-WebSocket-Extensions` offer, which RFC 6455 section 9.1 allows (the client then proceeds without the extension), and `tryParseFrame` rejects a frame with an RSV bit set, so a client that sends compressed frames anyway is closed with 1002 rather than misread. Autobahn sections 12 and 13 are therefore expected `UNIMPLEMENTED`. Tracked as an issue (see the progress note) rather than as bootstrap-grade work.
2. **The Autobahn nightly is not written in this change.** The development container has no Docker daemon (`docker ps` cannot connect), and `autobahntestsuite` is Python 2 software that only exists as a Docker image for CI use. A job script and an expected-results file that were never run against the real suite would be guesses, so none is checked in. What is needed is recorded in the progress note: a Lyric echo server with `maxMessageSizeBytes` 16 MiB and `idleTimeoutMs` 0, a CI runner with Docker and permission to pull `crossbario/autobahn-testsuite`, the expected-results file generated from a first real run and reviewed case by case, and a fix for the one blocker found by reading the kernel: it does not answer a client Ping (`FePing` is delivered to `onMessage`; the handler must reply, and `ws_e2e_tests.l` and `Ws.Kernel.Net`'s header document that as the contract). RFC 6455 section 5.5.2 says an endpoint MUST answer a Ping with a Pong carrying the same payload, so Autobahn cases 2.1 to 2.11 would fail. Changing that is a behaviour change for handlers that already reply (a second, unsolicited Pong is legal), so it is left for the PR that adds the nightly, with the issue linked.
