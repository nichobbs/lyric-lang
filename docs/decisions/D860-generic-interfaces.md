# D860: generic interfaces on --target dotnet and --target jvm

Status: accepted (#7791; the owner decided on 2026-11-25 to implement them on all three targets). Native follows in its own entry.

## Decision

1. **An interface may have type parameters and be implemented.** `interface Holder[T]`, `impl Holder[Int] for IntBox`, `impl[T] Holder[T] for Box[T]` and a call `h.get()` through a `Holder[Int]` value check, build as TIR and run. The checker already compared an impl against the interface with its parameters replaced by the impl's arguments (#8645); what stopped the build was the report **T0217**, which is now per target (item 2).
2. **T0217 is reported by the targets that cannot lower the construct.** `Lyric.Pipeline.MiddleEndOptions.genericInterfaces` is set by a bridge whose backend lowers an impl of a generic interface (dotnet and the JVM) and the checker's T0217 is dropped there; `--target native` keeps it until its slice, so a construct the checker accepts never reaches a backend that would miscompile it.
3. **A call through a generic-interface value is a typed `Callee.Interface`.** The checker records the call site (the signature is instantiated at the receiver's arguments), the TIR builder keeps the interface's arguments in `ifaceArgs` and registers the method under the signature as the interface declares it, over the interface's own parameters, so the verifier substitutes them (`noteGenericIfaceMethodSym`).
4. **A default method of a generic interface is inherited with the impl's arguments.** `Lyric.ImplDefaults` copies the body into an impl that omits it, with the interface's parameters replaced by the impl's arguments through `Lyric.Mono.substGenericsInDecl`; the checker finds it under the same arguments (`ImplPair.ifaceArgs`, `targetArgs`).
5. **dotnet reifies the interface.** The TypeDef carries the arity suffix and a GenericParam row per parameter and its members' signatures use VAR; an impl's InterfaceImpl row names a TypeSpec over it (`MImplData.ifaceTypeArgs`, built at lowering, when the interface's row is known), and the CLR wires the impl's methods by name and substituted signature, as it does for a generic external interface (D105), so no MethodImpl rows are written. A call through the interface is a TypeSpec-parented MemberRef (`MCallvirtGeneric`). An interface of a restored package registers the same way as a restored generic record.
6. **The JVM erases it.** The interface is one class whose methods take and return `Object`; an impl method with a narrower descriptor gets the synthetic bridge `implBridgeJvm` already wrote for a reference-typed difference, which now also unboxes a parameter and boxes a result for a primitive-typed impl method (`Holder[Int]`'s `get(): Int`). A value of a generic interface is narrowed to it before a call (`memberRecvClasses`), and an impl in another package finds the interface under `~iface~<Name>` in the extern seed (a generic interface is kept out of the bare-name seed, which would re-type every erased signature).
7. **Stays rejected.** A wrong argument count (T0216), a method whose signature differs from the interface's at the impl's arguments (T0106, T0107), a missing method (T0098) and a wrong argument type in a call through the interface (T0043) are reported as for a non-generic interface, and a `where` bound naming a generic interface is **T0233**; `testdata/reject/generic_interface_*` pins them.

8. **A package records its impl blocks.** `TPackage.impls` holds one `TImplDecl` per `impl` block that has members: the block's DefPath symbol (`Pkg::Target::$impl(Iface[args])`), its own type parameters, the target type, the interface and its arguments (all over `TParam(owner = the block's symbol, i)`, so a pass that instantiates the impl binds them from the target's instantiation), and the member symbols. The verifier checks that the interface exists, the types are closed over the block's parameters and each member is a function the package declares; the TIR passes keep the field. `Lyric.Tir.Mono` slice 2 (docs/70 phase 3c) reads it to give each instantiation of a generic interface its own interface symbol and to retarget the impls and upcasts.
9. **An implementor is a `Holder[Int]` only at the arguments its impl gives.** The checker compared a value's type with an interface by identity alone, so a record that implements `Holder[Long]` was accepted where a `Holder[Int]` is expected and the backends then called it with the wrong representation (a `ClassCastException` on the JVM). `ImplPair` records each impl's interface and target arguments and the check takes them (`symTableTypeImplementsAt`, with the impl's parameters bound from the value's type arguments); a type parameter stands for any argument, so a generic function's body is unaffected. The type arguments of a generic call are not read off an implementor, so `swapIn(longBox, 7)` binds `T` to `Int` from the literal and is **T0043**; `swapIn[Long](longBox, 7)` is accepted.

## Not done

A default method called on a concrete receiver whose `impl` is in another package than the interface (`Lyric.ImplDefaults` copies defaults only within a file, for generic and non-generic interfaces alike: the call fails at run time with `NoSuchMethodError` on the JVM and an unsupported-method error on dotnet), native (the interface's instantiations are separate vtable layouts, to be built with the TIR monomorphiser, docs/70 phase 3c mono slice 2, and the native backend's TIR lowering, phase 4a), a type parameter bounded by a generic interface (`where T: Holder[Int]`, reported as **T0233** instead of a type error in the body), and an interface method whose own type parameters appear in a generic-interface type (the method-level parameters are still erased to `Object` on dotnet).
