# D801 - A seeded property and fuzz suite for the HTTP/2 engine (docs/72 slice 2)

**Status:** accepted. Implements slice 2 of `docs/72-h2-client-role-plan.md`. Builds on D797 (the `H2Conn` client role); covers the frame codec (`Std.HttpEngine.H2Frame`), HPACK (`Std.HttpEngine.Hpack`) and `Std.HttpEngine.H2Conn` in both roles.

## Decision

1. **One suite**, `lyric-stdlib/tests/http_h2fuzz_tests.l` (20 tests), pure Lyric, no externs, so dotnet and the JVM must agree. It is run by `scripts/ci/h2conn-tests.sh` (already a single `ci.yml` step per target), so `ci.yml` does not grow.
2. **Determinism.** Every input is a pure function of an integer seed (a Park-Miller generator whose products fit a `Long`, identical on every target). Each generated case runs under `trapPanic`; a panic or failed assertion is rethrown as `<suite>: FAILED, seed=<n>: <message>`. `LYRIC_H2_FUZZ_SEED` (default 7200) moves the base seed and `LYRIC_H2_FUZZ_ITERS` (default 40 per property) scales the run, so `LYRIC_H2_FUZZ_ITERS=1 LYRIC_H2_FUZZ_SEED=<n>` replays one failure.
3. **Properties.**
   - Chunking invariance: the same bytes fed whole, one byte at a time, in random 1-64 byte chunks and in random 1-4096 byte chunks yield identical events and identical outbound bytes, for the frame decoder (random valid frames re-serialize byte for byte), HPACK (encode then decode across blocks sharing a dynamic table) and `H2Conn` server and client scripts (valid scripts must also never fail the connection).
   - Mutation robustness: bit flips, truncation, deletion, insertion, range duplication and random raw frames never panic, and after every feed the connection holds its invariants: it is failed exactly when it reported a connection error (which queued GOAWAY), the decoder buffers at most one frame, a header block buffers at most `SETTINGS_MAX_HEADER_LIST_SIZE`, the stream table stays within `maxConcurrentStreams` plus the retention window, window ceilings hold, outbound is a well-formed frame sequence ending on a frame boundary and is at most 4x the input plus a constant. Mutated HPACK blocks respect the caller's list limit and the table limit.
   - Bounded work on adversarial input (both roles where the attack applies): Rapid Reset cut off within one pair of `maxRapidResets`; a malformed-request flood cut off by the same stream-error budget; unfinished streams bounded by the concurrency limit; an empty-CONTINUATION flood cut off within `maxContinuationFrames`; a header block past the budget cut off within a few frames; an HPACK decompression bomb (about 47 MB of expansion from a 16 KB block, and a 200 000-reference block against the standalone decoder) stops at the list limit; an oversized frame declaration fails from the header alone; a frame dribbled one byte at a time buffers at most one frame; 20 000 PINGs plus 20 000 SETTINGS and 20 000 empty DATA plus WINDOW_UPDATE frames are answered with no amplification and no retained state.
4. **Long run.** The nightly `stage2-self-test.yml` (already building stage 2) gains one step that runs the suite on dotnet and the JVM with `LYRIC_H2_FUZZ_ITERS=3000` and a base seed derived from the day of the year, and files its existing tracking issue on failure. The PR gate stays at fixed seeds, so a PR run is never flaky.
5. **"Work" is measured structurally** (buffer sizes, table sizes, event and outbound counts, the frame and byte budgets), not by wall clock, so the assertions are deterministic on a loaded runner.

## Findings

The suite found no defect in the codec, HPACK or `H2Conn`: 20/20 on dotnet and the JVM at the default size, 5000 iterations per property on dotnet and 3000 on the JVM from other base seeds. The two failures during development were bugs in the suite (a `substring(start, length)` misuse and a frame split past the max frame size), not in the engine.

Observations recorded rather than asserted as defects: a peer can make the engine queue one PING ACK per PING and one SETTINGS ACK per SETTINGS without a limit, linear in the input (no amplification, but a driver that writes slowly must bound its outbound queue; the H2 server and client drivers already write synchronously under the connection lock). An HPACK bomb that fits the header-list budget on the wire is reported as `ENHANCE_YOUR_CALM` (the decoded list exceeded `SETTINGS_MAX_HEADER_LIST_SIZE`), not `COMPRESSION_ERROR`, which RFC 9113 6.5.2 permits.
