# D797 - `Std.HttpEngine.H2Conn` gets a client role (docs/72 slice 1)

**Status:** accepted. Implements docs/72 sections 1 and 2.2 to 2.3 and the slice-1 row of section 5. Answers docs/72 OQ-1 (a separate `H2ResponseTrailers` event, no role-neutral aliases) and OQ-2 (a role flag on the existing FSM, not a sibling module).

## Decision

1. **One FSM, two roles.** `H2Connection` stays the one connection type. `newServerConnection` is unchanged; `newClientConnection(settings)` builds a client (`H2Role = H2Server | H2Client`, read through `connectionRole`, `isClientConnection`, `isServerConnection`). Everything role-neutral (frame codec, HPACK, SETTINGS, flow control, PING, CONTINUATION assembly, field validation, the abuse guards) is shared code, so a hardening fix reaches both roles. The server corpus is the regression guard: `http_h2conn_tests.l` passes unmodified.
2. **Role state lives in a sub-record, because of the JVM arity limit (#6089).** `H2RoleState { role, nextLocalStreamId, highestPeerStreamId, expectPeerSettings, peerGoAwayLastStreamId }` replaces the two flat fields `lastPeerStreamId` and `expectClientSettings`, so `H2Connection` goes from 14 fields to 13 and `newClientConnection` verifies on the JVM (the loopback corpus runs there). `nextLocalStreamId` is a `Long`: the id after 2^31-1 does not fit `Int`, and a value above it is the exhausted state. The public `lastPeerStreamId(conn)` keeps its name and signature (always 0 on a client). `H2Stream` gains `phase`, `requestMethod`, `responseStatus` and `resetLocal` (10 fields).
3. **Client API.** `h2DefaultClientSettings` (1 MiB stream window, push off), `clientInitialBytes` (the preface plus SETTINGS; a wider connection window is the driver's `grantConnectionWindow`, since no setting carries it), `openStream(conn, headers, endStream): Result[H2OpenResult, H2OpenError]` (allocates the odd id, enforces the peer's `SETTINGS_MAX_CONCURRENT_STREAMS`, refuses after a GOAWAY, on exhaustion and over the peer's header-list limit, leaves the connection untouched on refusal; the caller serialises it with the write), `encodeRequestTrailers`, `sendPing`, `newClientConnectionAt` (a first id other than 1, so exhaustion is testable), and the queries `nextLocalStreamId`, `peerMaxConcurrentStreams`, `peerGoAwayLastStreamId`. `H2OpenError` cases are prefixed `Open...` because a union case name cannot repeat across unions in one package (`HeaderEncodingFailed` is taken by `H2SendError`); `OpenConnectionFailed` and `OpenHeaderListTooLarge` are additions to the plan's list.
4. **Events (additive, no aliases).** `H2InformationalHeaders`, `H2ResponseHeaders` (carries the whole validated list including `:status`, as `H2RequestHeaders` carries its pseudo-headers; `endStream` is a Trailers-Only response), `H2ResponseData` (same `wireLength` rule), `H2ResponseTrailers`, `H2StreamUnprocessed`. A server-role connection never emits them and a client never emits `H2RequestHeaders`/`H2RequestData`. The one exhaustive consumer, `Std.HttpServer`'s `processH2Event`, gains no-op arms for them; its behaviour is unchanged.
5. **Response validation** (RFC 9113 8.1, 8.2, 8.3.2) is `malformedResponseReason`: one three-digit `:status` (100 to 599) ahead of every regular field, no other pseudo-header, no 101 (HTTP/2 has no use for it, section 8.6), lowercase token names, clean values, no connection-specific field, a consistent `content-length`. A violation is a stream error `PROTOCOL_ERROR` and the block is still HPACK-decoded. The client phase machine (`H2PhaseAwaitFinal`, `H2PhaseBody`, `H2PhaseDone`) makes DATA before the final HEADERS a stream error, requires trailers to carry END_STREAM, rejects 1xx with END_STREAM, and treats HEAD, 204 and 304 as bodiless (any DATA there is a length mismatch). `isH2RequestHeaderListSafe` is the matching request-side precondition of `openStream`.
6. **GOAWAY on a client.** A received GOAWAY records its last-stream-id (a later one may only lower it, else connection `PROTOCOL_ERROR`, section 6.8), refuses new streams, and closes every locally opened stream above it with `H2StreamUnprocessed`, which is retry-safe and distinct from `H2PeerReset(H2RefusedStream)`. The GOAWAY a client sends names stream 0 because its peer opens none, so `connFail` and `sendGoAway` needed no role branch for the last-stream-id; they read `highestPeerStreamId`.
7. **Role-gated abuse accounting.** Rapid Reset (CVE-2023-44487) accounting is server-side and is skipped for a client, where a server-sent `RST_STREAM` is routine. PUSH_PROMISE stays a connection `PROTOCOL_ERROR` (the client always advertises ENABLE_PUSH 0, section 6.6) with a role-specific message; an even id in HEADERS, DATA, RST_STREAM or WINDOW_UPDATE is a connection error.
8. **Frames the server queued before it saw our reset are discarded, not errors** (section 5.1, "closed"). A stream this endpoint sent `RST_STREAM` on (or that a GOAWAY closed) keeps `resetLocal`; HEADERS for it are decoded and dropped (HPACK stays in sync, section 4.3), DATA is dropped with its connection window reclaimed, and a server RST for it raises no event. A frame for a closed stream that was not reset locally keeps the severities the server uses (stream error for DATA and for half-closed (remote) HEADERS; for HEADERS on a fully closed stream the client raises connection `STREAM_CLOSED`, section 5.1). A pruned old id is treated like a locally reset one.

## Re-count of the 31 server-specific sites

docs/72 section 1.3 was written against a file that has since gained no new server sites; line numbers drifted but all 31 were found and handled: 1 header text, 2 construction, 3 `clientInitialBytes`, 4 default client settings, 5 `createStream` (neutral), 6 `isIdleStreamId`, 7 `pruneClosedStreams` (`streamIdHighWater`), 8 `handleHeaders`, 9 `beginNewStreamHeaders` (server only; the client goes to `handleClientHeaders`), 10 `beginTrailerHeaders` (client: `beginResponseHeaders` and `routeResponseBlock`), 11 `ContinuationState` (unchanged: the phase, not a header kind, decides), 12 `H2Stream`, 13 `malformedResponseReason`, 14 `finalizeHeaders` (`finalizeResponseHeaders`), 15 DATA content-length (neutral), 16 `isH2RequestHeaderListSafe`, 17 Rapid Reset gating, 18 and 19 GOAWAY last-stream-id (neutral, see 6), 20 `handleGoAway`, 21 `handlePushPromise`, 22 `expectPeerSettings`, 23 (none), 24 `openStream` and `encodeRequestTrailers`, 25 and 27 and 28 and 31 (none), 26 `markEndStreamSent`, 29 `sendPing`, 30 queries.

## Deviations from docs/72

`malformedResponseReason` takes the header list only (informational and final blocks share every rule). No `H2StreamRefused` case (the plan already expressed it as `H2PeerReset(H2RefusedStream)`). `clientInitialBytes` does not append a connection WINDOW_UPDATE. `ContinuationState.isTrailer` was kept. `serverInitialFrame` now requires a server connection. The extra `resetLocal` field and the client leniency in item 8 are not in the plan; they are what RFC 9113 section 5.1 requires of an endpoint that cancels.

## Consequences

The client FSM has no timers and no I/O; keepalive, deadlines and connection reuse are the driver's (docs/72 slice 5). Slices 2 and later build on `openStream` and the events above.
