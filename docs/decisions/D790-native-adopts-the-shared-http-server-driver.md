# D790 - Native adopts the shared HTTP server driver and gains h2 (docs/73 slice S5)

**Status:** accepted. Extends D789 (the JVM slice, S4), D788 (the shared driver, adopted by dotnet), D786 (the `Std.HttpServerHost` seam) and D780 (gates). Closes N9.5 / #6106 (native h2) and the native half of defect 2 of the D780 baseline. 

## Context

After S3 the native `Std.HttpServer` was the last per-target server: `_kernel_native/http_server.l` (2018 lines) was HTTP/1.1 only, closed a connection that negotiated `h2`, had no `WithLimits` variants and, under connection-per-request load, completed nothing at 64 concurrent connections and grew about 12 KB per accepted connection (D780 defect 2, not root-caused). D788 recorded what S5 still owed: release the shared driver's per-listener and per-stream locks and semaphores on native, keep a parked puller's objects alive (#6802), and run the old native self-tests under AddressSanitizer.

## Decision

1. **The native kernel is deleted.** `lyric-stdlib/std/_kernel_native/http_server.l` is removed; native compiles `std/_kernel/http_server.l` over `_kernel_native/tcp_host.l` and `_kernel_native/http_server_host.l`. With the JVM kernel gone too (D789), the driver moved to `lyric-stdlib/std/http_server.l` (D780's last step, a separate commit); `lyric.full.toml` registers it there, and since it no longer sits under the audited `_kernel/` tree its one `@axiom` (backing `@sendable` on `HttpListener`) is no longer counted in docs/17's tables (the .NET total is 40 stable).
2. **Root cause of defect 2.** The retired kernel created every connection thread joinable (`lyric_thread_create`) and joined them only in `stopListener`. A finished but unjoined pthread keeps its stack mapping (about 12 KB resident, two memory mappings) and its retained closure, so the process leaked per connection and, at about 32 000 connections, reached `vm.max_map_count`, after which no thread could be created and no connection served: the "0 requests completed, 1.4M resets" of the baseline. The shared driver starts detached threads (`tryStartTask`), so nothing accumulates: 1.23 million `Connection: close` exchanges move the server's RSS from 3.0 MB to 4.5 MB with 6 descriptors and 34 threads at the end. `llvm_http_server_self_test.l` item R pins it (the line count of `/proc/self/maps` may not grow by more than 300 over 3000 connections; the old kernel fails it, verified).
3. **Release of the driver's primitives (a no-op on dotnet and the JVM).**
   - Per listener: `stopListener` frees `connLimit` and `quiet` once the accept loop and every connection task have ended. `guard` and `available` are freed only when `waitingPullers`, a count kept under `guard` around the wait in `tryNextContext`, has reached zero; the stop wakes every puller, so it waits (bounded by the grace period) for them to leave and, if one never does, keeps those two slots rather than free them under it (#6802). `HttpListener.released` is set under the lock and read without it at the entry of `tryNextContext` and `stopListener`, so a call that begins after the first stop returned still answers (`None`, return) and never touches freed objects. A thread must not start a pull at the very moment another thread's `stopListener` is returning; this is documented on `stopListener`.
   - `taskFinished` posts `quiet` after releasing the lock, since the stopper frees the lock when it sees `quiet`.
   - Per HTTP/2 connection: one lock (`H2Link.guard`) is shared by the connection's queues; `wake`, `inCredit`, `readerDone` and `unusedDone` are the other slots. They are freed by the last party to leave the link (`refs`: the connection task, the reader task, the drain watchdog while it runs, and each dispatched exchange until its handler has finished with it). Per stream, `credit` is freed by the second of the two sides (`sides`: connection task, handler) to finish, the handler's side being idempotent (`handlerDone`), so a handler that completes a response twice or writes after it ended is ignored instead of touching freed storage. A request the listener discards (stop, or queued after it) aborts its stream and gives the handler's count back (`discardContext`).
   - The connection task shuts the socket down and waits for the reader (`readerDone`) before it closes the socket, so the reader never reads a closed connection or a freed TLS handle (previously it relied on closing the descriptor waking a blocked read, which does not hold on Linux).
4. **TLS and the transport (native).**
   - An OpenSSL connection is not safe for one thread reading while another writes, which an h2 connection does. `lyric_tls.c` wraps each connection (`tls_conn`: the `SSL*` and a mutex); every `SSL_read`, `SSL_write` and `SSL_shutdown` runs under it. A blocking read first waits for the socket outside the lock (`tls_wait_readable`, bounded by the socket's receive timeout, `SSL_has_pending` first), and `SSL_MODE_AUTO_RETRY` is off, so a read that meets a post-handshake message returns instead of blocking for the next record while holding the lock (found by a real deadlock in item B under AddressSanitizer). A record split across packets still holds the lock until it is complete, which delays that one connection's writes, never another's.
   - Server connections set `SSL_OP_IGNORE_UNEXPECTED_EOF`: a client that half-closes without `close_notify` (the #8683 case) is read as end of input and its response is still written, as on dotnet and the JVM; OpenSSL 3 otherwise sends a `decode_error` alert and refuses to write.
   - Every socket sets `TCP_NODELAY` (accepted and connected). Without it h2 over TLS served 1.8k requests/s (the 40 ms delayed-ACK stall D780 found on the JDK server); with it 25k to 34k.
   - `hostStopListener` now also stops the listening socket (#9184): after the wake-pipe signal `lyric_sock_listener_refuse` calls `shutdown` and `dup2`s an unconnected socket over the descriptor, so a connect after the stop is refused while the descriptor number stays allocated until `hostCloseListener` (the fd-reuse hazard of #6883 cannot arise). `tcp_host_tests.l` (16) and `http_timeout_tests.l` (3) now pass on native and join the native lists. Windows has no `dup2`: its twin does nothing, so the Windows listener keeps listening until `hostCloseListener`.
   - **Windows offers `http/1.1` only** (`alpnPreference` is `@cfg(target_os = "windows")`): Schannel's connection state has the same thread-safety limit and `lyric_tls_win32.c` has no per-connection lock yet. Not built or run here (no Windows toolchain in the container); the Windows twin of `lyric_sock_listener_refuse` was added by reading only.
5. **Driver changes for native codegen.** `newList()`/`newMap()` as a record-constructor argument has no element type on native (`N0007`); the driver binds them to annotated locals first (`newList[T]()` is used nowhere: it fails to resolve on dotnet for `newMap`). `ServerFifo` takes its lock from the caller (`newFifoOn`). No behaviour change on dotnet: `http_server_dotnet_tests.l` 33/33, `http_server_stop_tests.l` 13/13, `http_server_host_tests.l` 15/15, `tls_tests.l` 30/30 on dotnet.
6. **Tests.** `llvm_http_server_self_test.l` has 18 cases under AddressSanitizer (LeakSanitizer on): item C now does an h2 round trip (raw frames: SETTINGS, `:status 200` HEADERS, a DATA frame) where the old one asserted that h2 was refused; item H uses `tryNextContext` and joins its pullers; item R is the churn case. `tls_tests.l`'s one-request server uses `tryNextContext` (a rejected client never sends a request and the stop would panic `nextContext`, which ends a native program). `http_server_stop_tests.l`, `tcp_host_tests.l` and `http_timeout_tests.l` join the native lists, and `h2-smoke.sh native` (curl `--http2` and `--http1.1`, h2load, the scheduler checks) runs in `native-backend-self-tests.sh`.

## Not verified, follow-ups

- Windows: the `@cfg` ALPN value, `lyric_sock_listener_refuse` in `lyric_sock_win32.c` and the unchanged Schannel path were not built or run; `scripts/ci/windows-native-tests.sh` still runs `llvm_http_server_self_test.l`, whose item C expects `http/1.1` on Windows. A per-connection lock in `lyric_tls_win32.c` would lift the restriction.
- macOS: `dup2` and `shutdown` on a listening socket are POSIX but were run on Linux only.
- B6 (30 minute soak) and B7 are not measured; the churn run above (1.23M connections) and the 18 ASan cases are the leak evidence.
- The residual window noted on `stopListener` (a first call to `tryNextContext` from another thread at the instant the stop returns) is documented, not closed: closing it needs an atomic counter in the seam (not available on all targets without touching the JVM twin).
