# D802 - `Grpc.Client` and `Grpc.Wire`: the pure-Lyric gRPC client on `H2Client`, `openChannelWith`, and the `legacy-client` feature (docs/72 slice 6)

**Status:** accepted. Implements the client half of slice 6 of `docs/72-h2-client-role-plan.md` (§3.8, §4.2, §4.5). Builds on D800 (`Std.HttpEngine.H2Client`), D798 (`Std.Zip` gzip), D799 (client TLS) and D287 (the pure-Lyric h2c server, unchanged except that it now frames messages with `Grpc.Wire`). It supersedes, for the client, D281's choice of `Grpc.Net.Client` and grpc-java; the kernels stay, selectable, until slice 10.

## Decision

1. **`Grpc.Wire`** (`lyric-grpc/src/wire.l`, `@pure`): `frameMessage(payload, compressed)`, `MessageReader` (chunk-based reassembly across and within DATA frames, an oversize prefix refused before its payload is buffered, a 4 GiB prefix handled as a `Long`), `compressMessage`/`decompressMessage` over `Std.Zip` gzip with the receive limit as the output bound, `encodeTimeout` (at most 8 digits, rounded up through `m`, `S`, `M`, `H`), `isGrpcContentType`, and the three status tables: `statusFromHttpStatus` (400 Internal, 401 Unauthenticated, 403 PermissionDenied, 404 Unimplemented, 429/502/503/504 Unavailable, else Unknown), `statusFromFailure` (RST_STREAM and connection failures; REFUSED_STREAM, GOAWAY-unprocessed and lost connections Unavailable, CANCEL Cancelled, ENHANCE_YOUR_CALM ResourceExhausted, INADEQUATE_SECURITY PermissionDenied, every other code and NO_ERROR without a status Internal) and `statusFromFields` (`grpc-status` with the percent-decoded `grpc-message`; a non-integer is Internal, an out-of-range integer Unknown).
2. **`Grpc.Client`** (`lyric-grpc/src/client.l`): one implementation for dotnet and the JVM, no extern. `Grpc.openChannel`, `closeChannel`, `callUnary`, `openServerStream`, `nextMessage` and `closeStream` keep their signatures and call it by default.
3. **Pooling** (OQ-9): a channel owns up to `ChannelOptions.maxConnections` connections (default 1), dialed lazily. A call takes the first open connection with a free stream; if all are full and the limit allows, a connection is dialed; otherwise calls queue first-in first-out (a ticket queue, re-checked every 2 ms, so the call's deadline applies while it waits; no condition variable exists in `Std.HttpServerHost`). GOAWAY-draining connections are retired and replaced by the next call; Closed ones dropped. Idle connections are closed by a per-channel janitor task that exists only when `idleTimeoutMs > 0` (30 minutes by default) and ends at `closeChannel`. After a failed dial, calls fail with `Unavailable` (when no connection exists) until a jittered exponential backoff (1 s initial, x1.6, 20 percent jitter, 120 s cap, all options) elapses. Keepalive is `ChannelOptions` pass-through, off by default (OQ-5).
4. **Transparent retry**: exactly once, only when `h2FailureIsRetrySafe` (REFUSED_STREAM, above a GOAWAY's last-stream-id) and before any response message was delivered; the retry re-acquires a connection, with the deadline unchanged and `grpc-timeout` recomputed.
5. **Response handling**: `:status` first (non-200 maps through the table unless a `grpc-status` is present), then `content-type` must be `application/grpc` or a `+`/`;` form (else Unknown naming the content type), Trailers-Only is read from the headers, messages are reassembled and limited to `maxReceiveMessageBytes` (4 MiB, ResourceExhausted, also for the decompressed size), a missing `grpc-status` in trailers is Unknown, a stream that ends without trailers or inside a message is Internal, a unary call needs exactly one message (Internal otherwise). A server's RST_STREAM CANCEL at or within 100 ms of the call's own deadline is DeadlineExceeded: grpc-java enforces the `grpc-timeout` it is sent and its reset can arrive a poll interval before the client's (found by `client_jvm_tests.l`).
6. **API additions**: `Grpc.openChannelWith(address, ChannelOptions)` (TLS `trust`/`identity`/`minVersion` from `Std.Tls`, `maxReceiveMessageBytes`, `maxConnections`, `connectTimeoutMs`, keepalive, `idleTimeoutMs`, `userAgent`, reconnect backoff; `ChannelOptions` is a ref record from `Grpc.defaultChannelOptions()`, validated by `channelOptionsProblem`), `GrpcCompression` with `Grpc.withCompression`, and `GrpcCallOptions.compression` (a new field: the record is only constructed in `grpc.l`). Request compression is opt-in; every request advertises `grpc-accept-encoding: identity,gzip` and gzip responses are decoded. `Grpc.Client.channelConnectionCount` is a diagnostic. Addresses keep the `http://`/`https://` forms of `parseAddress` (IPv6 literals in brackets, default ports 80 and 443); a bare `host:port` is still refused, as on the JVM.
7. **`legacy-client` feature** selects the SDK kernels (`Grpc.Kernel.Net`, `Grpc.Kernel.Jvm`) for the six client functions instead of `Grpc.Client`; `openChannelWith` then returns `Err`. The `dotnet` and `jvm` features keep selecting the server kernels, rate limit and the manifest's SDK dependencies, so this is a transition aid removed with the kernels in slice 10. The pure client is the default on both targets.

## Deviations from docs/72

- `Grpc.Client` is `client.l` and `Grpc.Wire` `wire.l` (the plan said `client_h2.l`).
- `H2Client.h2Close` sends no GOAWAY (D800), so an idle close and `closeChannel` simply close the socket.
- Queueing past `MAX_CONCURRENT_STREAMS` polls (2 ms) instead of blocking on a condition: the seam has none (D800, OQ-7).
- Not in this slice: the server half of `Grpc.Wire` beyond framing (decode of compressed requests, `grpc-timeout` enforcement are slice 8), removal of the kernels and SDK dependencies (slice 10), native (slice 7).

## Findings recorded

- JVM backend: a value bound by a pattern from a generic container loses its static type. `match r { case Ok(b) -> list.add(b) }` with `r: Result[slice[Byte], E]` and `list: List[slice[Byte]]` throws `ClassCastException: [B cannot be cast to [Ljava.lang.Object;`, and a field store through a value bound by `case Some(p)` of an `Option[RefRecord]` fails with `NoSuchFieldError` on `java.lang.Object`. Both pass on dotnet. The client avoids them (the store happens on a typed parameter) and the test peer binds through a typed `val`.
- Cross-package `Ok`/`Err` are ambiguous in a package that imports `Grpc.Types` (`GrpcStatusCode.Ok` is a bare case there).
