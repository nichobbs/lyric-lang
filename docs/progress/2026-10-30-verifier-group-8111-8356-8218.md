# Verifier: out/inout ensures, generic callees, record-body methods, `[..].toSlice()` (#8111, #8356, #8631, #8218)

## A callee's `ensures:` about an `out`/`inout` argument reach the caller (#8111)

After `inc(a)` with `func inc(x: inout Int) ensures: x == old(x) + 1`, the caller
now proves `a == a0 + 1`. `translateResolvedCall` records the symbol the
parameter has after the call under the argument variable and the call's span
(`VEnv.outPosts`); `havocOutArgs` binds the variable to it instead of an
unrelated new value when the effect analysis finds exactly one call changing
that variable in the expression and the argument is just the variable's name.
Fields, elements, a variable also changed by an unresolved or second call
keep a fresh value. Tests: "a callee's ensures about an out or inout argument
reach the caller (#8111)".

## Generic callees and record-body methods (#8356, #8631 items 1 and 2)

- A generic callee's type arguments are inferred from its arguments
  (`matchArgSortParams`), substituted into its parameter and result sorts and
  contract, and each instance is its own uninterpreted function. A type
  parameter no argument fixes fails closed (V0033).
- A method declared in a record body is registered as a callee (`R::m`) when it
  takes `self` and is the only method of that name; its contract and `@pure`
  body are applied at a call, with the record's type parameters read off the
  receiver's sort. Methods join the contract-cycle graph.
- Generic records and unions are value types (so a `@pure` call over them is
  unfolded) when their type arguments are value sorts.

The example in #8356 (`getV` with no contract) is still not provable, correctly:
the method promises nothing; mark it `@pure` or give it `ensures: result == self.v`.
Generic aliases of `Result`/`Option` (#8631 item 3) are not done.
Tests: "a generic callee is applied at the type arguments its arguments fix
(#8631)", "a method declared in a record body is applied by its contract
(#8356)", and the updated generic-record-method cases.

## `[1, 2].toSlice()` (#8218)

The checker types a bracket literal that is the receiver of `.toSlice()` as
`array[N, T]` (it was a `slice`, which has no `toSlice`, T0120 on dotnet and
J008 on the JVM). Test: `fixed_array_self_test.l` on dotnet, JVM and native.

## `==` on slices on the JVM (#8218)

`a == b` on two `slice[T]` values emitted an integer compare (`if_icmpeq`) on
array references, which the JVM verifier rejected (`VerifyError`). It now
compares the arrays by reference (`if_acmpeq`/`if_acmpne`), as dotnet does and
docs/01 states. Test: `fixed_array_self_test.l` ("== on a slice compares by
reference ...") on dotnet and the JVM.
