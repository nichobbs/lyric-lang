# The toolchain and `--target dotnet` output move to .NET 11

`bootstrap/global.json` pins SDK 11.0.100, the entry point's ILCompiler reference is 11.0.0, and `Lyric.DotnetTarget.dotnetMajor()` is 11. A program built with `--target dotnet` now carries a `runtimeconfig.json` asking for `net11.0` / `Microsoft.NETCore.App 11.0.0`, `lyric publish` packs into `lib/net11.0/`, and the default `[nuget.options] target` is `net11.0`. Users need the .NET 11 runtime (the SDK for `--shape aot`).

## Native AOT (`--shape aot`)

`Lyric.Release` drives ILCompiler and the linker itself, with the arguments the SDK's `Microsoft.NETCore.Native.targets` would pass. Those changed in .NET 11:

- `--stacktracedata` takes a value; the SDK passes `--stacktracedata:frames`. The bare flag made ILCompiler 11 take the next argument as the value (`Unknown stack trace data: --scanreflection`).
- The exported debugger symbol is `DotNetRuntimeContractDescriptor` (was `DotNetRuntimeDebugHeader`), and on Linux the linker keeps it with `-Wl,-u,DotNetRuntimeContractDescriptor`.
- The VxSort stub (`libRuntime.VxsortDisabled.a`) is linked on arm64 as well as x64.
- `System.IO.Compression.Native` depends on zstd: `libzstd.a` from the pack, or `-lzstd` where the pack has none.
- On macOS a source-built SDK (Homebrew's) ships no brotli or zstd archives and links the system libraries, as its own targets do. The link adds Homebrew's library directory and `-Wl,-dead_strip_dylibs`, so a program that never calls them does not depend on them at run time.

## Scripts

`scripts/ilverify-selfhosted.sh` and `scripts/selfhost-check.sh` install the `dotnet-ilverify` of the pinned SDK's major version instead of 10.0.0.

## Docs

README, the book (preface, chapters 1 and 20, appendix B), `docs/21-nuget-linking.md` and the VS Code `lyric.toml` schema name .NET 11.

## Verification

On macOS 27 (arm64) with SDK 11.0.100 (Homebrew): `make lyric` builds; a built program runs and its `runtimeconfig.json` names `net11.0`; `--shape aot` builds a native binary that runs and links only system libraries; `scripts/ci/release-native-aot-smoke.sh` and `scripts/ci/byte-println-e2e.sh dotnet` pass; the Native AOT publish of the CLI (`scripts/ci/native-aot-publish-lyric-cli-macos.sh`) passes once the linker can find Homebrew's OpenSSL (`LIBRARY_PATH`), which the Microsoft SDK on CI does not need; 22 compiler self-tests (the 17 that write a `runtimeconfig.json`, `cli_publish`, `release`, `manifest`, `auto_ffi`, `bitwise`) and the `lyric-session` tests pass. Linux and Windows were not run locally; CI covers them.

## Two defects .NET 11 exposed

- **`Float.toByte()` and `Double.toByte()` outside 0..255.** The emitter lowered them to a bare `conv.u1`, whose result for an out-of-range float is unspecified: the runtime wrapped it up to .NET 10 and saturates to 255 from .NET 11, so `(300.75f32).toByte()` gave 255 instead of 44 (`float32_self_test.l`). The conversion now truncates to `Int` first (`conv.i4`, then `conv.u1`), which is what the JVM does and what the reference says ("truncates, then wraps modulo 256").
- **`ldobj`/`stobj` through a reference to a plain value type** (`inout`/`out` parameters of `DateTime`, `TimeSpan`, `Guid`) named the type with a TypeSpec whose blob was `VALUETYPE <type>`. ECMA-335 II.23.2.14 does not allow that form; ilverify 10 let it through and ilverify 11 reports `BadTypeSpec` (`byref_value_type_self_test.l`, `byref_extern_struct_dotnet_self_test.l`). The instruction now carries the type's own TypeDef or TypeRef token.
