# MSIL: an unhinted bracket literal with a call, member or index element is built as its checked `slice[T]` (D-progress-1056)

D-progress-1055 covered an unannotated binding. The same `List<object>` was still built for a literal that is a lambda's result, a tuple element, a `Some(...)`/`Box(...)` argument, a slice method's receiver, or an element of another literal used as a `for` iterable; handed to a `String[]` extern parameter it printed an empty string or crashed with `AccessViolationException`. The checker now records the checked slice type of every such literal (`recordListLiteralType`), so `Lyric.Mono` binds it to a local of that type and the array arm builds it. Hinted positions are withdrawn (`noteListLiteralInListContext`): a first form that recorded them printed `8589934600` for `sum([1, 2, n])` against a `slice[Long]` parameter. Tests: `slice_literal_binding_array_self_test.l` (runtime, 14 cases) and three `typechecker_self_test.l` cases. A closure call's result, typed `object` by the uniform function ABI, is converted to the `T[]` it carries (`lowerFuncValueInvokeMsil`, `emitObjectToSliceArrayMsil`), which also removes the `ilverify` StackUnexpected the lambda cases showed.
