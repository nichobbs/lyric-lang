# 2026-11-14 - lyric-ecosystem: AWS Emulator and credentials, Hangfire, broker recovery, first native packages (docs/71 phase 4)

Follows `2026-11-13-ecosystem-net-and-memcached.md`. nichobbs/lyric-ecosystem#6 and #7.

**AWS backends verified against AWS Emulator.** `Lyric.Mq.Sqs` and `Lyric.Storage.S3` had only been run against ElasticMQ and MinIO, neither of which checks a signature the way AWS does. Their integration suites now also run, on dotnet and the JVM, against AWS Emulator 1.0.341, which rejects a request not signed with the key it generated for the run. It also follows Amazon where MinIO differs: creating a bucket the account already owns is a 200 in `us-east-1`, which corrected one test and the `createBucket` documentation. The emulator serves HTTPS from its own CA, so both packages gained `withCaCertificate` and `withExclusiveCaCertificate` (the names `Lyric.Redis` uses), which also serves S3-compatible stores behind a private CA. Neither package has been run against AWS itself.

**`Lyric.Aws.Credentials`.** A shared pure-Lyric package: static and environment providers, the shared config and credentials files (AWS's INI dialect, `AWS_PROFILE`, `credential_process`), the container endpoint, IMDSv2, web identity through STS, the default chain in the SDK's order, and a cache that refreshes before expiry without stampeding. A chain passes over a provider that is not configured or unreachable and stops at one that is configured but broken. `Aws.Retry` is the standard policy (three attempts, full jitter, `Retry-After`). Both AWS backends resolve and re-sign on every attempt and retry only what is safe: throttling and a connection that never opened always, a 5xx or timeout only for idempotent requests. Profiles that need `source_profile`, `role_arn` or SSO are refused as unsupported. The container, IMDS and web identity providers have run only against in-process fakes.

**`Lyric.Jobs.Hangfire`** (dotnet). `Jobs.JobScheduler` on Hangfire.Core 1.8.25 through `extern type` and auto-FFI: jobs are built from `InvocationData` and name a Lyric top-level function, so real `BackgroundJobServer` workers run the application's handlers. Storage is in-memory or PostgreSQL (`Hangfire.PostgreSql` 1.21.1). SQLite was tried and removed: `Hangfire.Storage.SQLite` 0.4.3 answers a job's state from its history (a retried job read as `Failed`) and its distributed lock can lose a wake-up and hold a job back 90 s; the second was found by a CI failure and reproduced under constrained CPU.

**Heart-beats and reconnecting** in `Lyric.Mq.ActiveMq` (STOMP) and `Lyric.Mq.RabbitMq` (AMQP 0-9-1), on by default. After a loss the client reconnects with capped, jittered backoff and restores its subscription or consumer and, for RabbitMQ, the topology it declared. A publish while disconnected fails as not sent; one in flight at the drop reports an unknown outcome and is never resent; an ack for a delivery from the lost connection is an error (RabbitMQ deliveries carry a channel epoch, so a reused delivery tag cannot settle another message). `Lyric.Net` gained `Net.Threads` for the background thread.

**Native.** `Lyric.Net` has a third socket kernel, on the standard library's native seam (`Std.TcpHost`, `Std.IoWait`, `Std.Task`); `Lyric.Redis` and `Lyric.Aws.SigV4` needed no source change. All three pass their suites on `--target native` on Linux, in a new CI job. `lyric test --manifest` refuses `--target native` (#6815), so the repository's CI builds each test module into an executable with a script that mirrors `TestSynth.synthesizeNative`; it should be deleted when the command exists.

**Issues filed:** #9088 (native: a record named like a union case of another package), #9089 (native: `String + Char`, which breaks `Std.Xml`), #9090 (native: `Std.Http` ignores request timeouts; `lyric-testing`, `lyric-storage`, `lyric-jobs`, `lyric-db` and `lyric-mail` do not build; manifest tests), #9094 (MSIL: `List` of a cross-package extern type), #9095 (native NuGet assets not deployed; auto-FFI gaps met binding Hangfire).
