# lyric-access: AccessKit adapters for the native lyric-ui host (docs/67 G10, #8489, D376)

- `lyric-access/` (`Lyric.Access.Core`): `Access.Plan`, node numbering, text runs and selections, update plans; 11 tests passing on `--target dotnet` and `--target jvm` (also in `scripts/ci/ui-jvm-suites.sh`).
- `lyric-access/platform/` (`Lyric.Access`): `Access.Kernel.Accesskit` generated by `lyric bindgen` from accesskit-c 0.23.2 (Linux, macOS and Windows files), `Access.Platform` (AT-SPI, NSAccessibility and UI Automation adapters, request queue), the request-layout check, and `examples/smoke`. The library comes from the pinned release archive; Linux arm64 builds it from source (`scripts/ci/build-accesskit.sh --source`).
- `Ui.Native.Run` attaches the adapter before showing the window, publishes the tree after each frame, reports window focus and bounds, and carries out requests through `resolveRequest`; `accessTree`/`accessRequest` on the headless host. `lyric-window` gained `windowBounds` and the `WindowMoved`, `WindowFocusGained` and `WindowFocusLost` events.
- `Ui.Native.Access`: href links offer a click; grid cells are no longer doubled (19 tests).
- CI: AT-SPI smoke test in `scripts/ci/ui-native-e2e.sh` (Linux x86-64 and arm64), UI Automation smoke test in `scripts/ci/access-platform-e2e.sh` (Windows), kernel/layout check and adapter attach on macOS.
- Open: an NSAccessibility client or VoiceOver run on macOS CI (#8799).
