# CI, test and docs hygiene batch (group:ci-test-docs-hygiene)

A sweep of stale CI scripts, unwired tests and wrong cross-references.

- **CI scripts.** `run-single-file-examples.sh` starts each example server in its own process group and kills the group, then asserts port 8080 is free (#7982). `ui-browser-e2e.sh` asks the OS for a free port and passes it to `examples/ui-customers` through `LYRIC_UI_PORT` (#8006). The dead `bootstrap/src/Lyric.Cli` branches were removed from `build-example-packages.sh`, `ecosystem-library-builds.sh` and `stage-stdlib-dlls-localdep-resolver.sh` (#7688). The self-hosted `runs-on` selection in `ci.yml` now falls back to `ubuntu-latest` for fork pull requests, so untrusted PR code never reaches the self-hosted pool (#6999).
- **Tests.** `byte_arithmetic_self_test.l` already passed and `option_match_self_test.l` was ported from `@test func` items to `test` blocks; both are now in `TEST_EMITTER_FILES` and in the dotnet and JVM compiler self-test batches (#8243). `lyric-compiler/fixtures/builtin_name_override/` is a two-package fixture proving that an imported package's `newList`/`mapGet` overrides the builtin intrinsic on dotnet, JVM and native (`scripts/ci/builtin-name-override-test.sh`, #7675). `examples/agent/basics.l` was ported to current syntax and runs on dotnet and JVM in `test-multi-package-examples.sh` (#7606).
- **Docs.** The `Makefile` and `CLAUDE.md` fast-loop text now says `stage1-fast` leaves the `Lyric.Compiler.dll` bundle that `lyric test` links stale, and that `make selfhosted-compiler` refreshes it. The book's `[contracts]` cross-references point at the language reference sections that hold the content (#7743). The native `toUpper` note in docs/01 now states that the JVM applies `SpecialCasing` expansions such as `ß` to `SS` (#7076). Decision and work-item cross-references from the native `Std.Char` entry were corrected (#7075), the duplicate `N9.8` ids renumbered (#7074), and two lines that a merge had moved from `docs/03-decision-log.md` into `D-progress-0896` were put back (#7073). The `startWorkers`/`serveStreaming` doc comments in `lyric-web` were re-attached to the right functions (#6982).
