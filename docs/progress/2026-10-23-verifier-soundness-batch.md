# Verifier soundness batch: bounds, IEEE floats, ranges, `@pure` unfolding, sibling records

`lyric prove` accepted programs that panic or compute differently at run time. This batch closes the holes found by the soundness reviews of #8140 and nearby, and models three constructs it used to leave unknown. Issues: #8157, #8141, #7883, #8354, #8218, #8143, #8336, #8306, #8142 (already fixed on main, regression tests added).

- **Index bounds (#8157).** `xs[i]` on an array, slice or `String` carries `0 <= i < length`. The length is one uninterpreted function (`$len`) of the value; `.length` and `.count` read it, so a `requires: i < xs.length` discharges the obligation. An `array[N, T]` parameter with a literal `N` carries `length == N`. The element is a fresh value of the element sort. A `List`, `Map` or other receiver fails closed (`V0033`): `add` and `clear` change a list the verifier models as one value, so no length can be named.
- **Floats (#8141, #7883).** `Double` is the SMT `Float64` with round-to-nearest-even arithmetic and IEEE comparisons, so `x == x` and `x + 1.0 > x` are refuted and `x <= x or x != x` is proved. The trivial discharger no longer closes a float comparison by reflexivity. `Float` (64-bit on dotnet and native, 32-bit on the JVM) and `%` on floats fail closed. The `V0013` "replaced NaN with 0.0" warning is gone: non-finite literals are rendered faithfully. Compound `/=` on a float renders as `fp.div`.
- **`@pure` unfolding.** A `@pure` callee was unfolded at every call, so `probe(xs) == probe(xs)` held across an `xs.add(1)` between the calls. It is now unfolded only when every argument is a value.
- **Ranges (#8143).** An assignment to a variable of an inline range type carries the range as an obligation; the store is range-checked at run time.
- **Sorts (#8354, #8218).** `sortEq` compares a datatype's type arguments. `array[N, T]` and `slice[T]` are distinct sorts (`SArray`, `SSlice`); `==` on a slice fails closed since dotnet compares slices by reference.
- **Scope (#8306, #8336).** The records and distinct types of the package's other files are in scope for a proof. `n.twice()` for `func Int.twice(self: in Int)` resolves to it, as `Int.twice(n)` already did.

Left open, with the concrete gap noted on each issue: #8111 (out/inout `ensures:` linked back), #8110 (heap model, record-body methods), #8103, #8168, #8356 (record-body method calls are not callees), #8394 (`select`/`store` for element values), #7806, #8245 and #8188 (file-set agreement with `Lyric.PackageMerge`, symlinks), #8160 (the vcgen split, deliberately not mixed into a soundness change).
