# MSIL: an unannotated binding's list literal is built as its checked `slice[T]` (D-progress-1055)

`val parts = ["a", "b", n.toString()]` is a `slice[String]` to the type checker, but the MSIL no-hint `EList` arm chose the representation from the elements' syntax (`inferHomogeneousListElemTypeMsil`). An element that is a call, a member access or an index has no type that peek can name, so the literal was built as a `List<object>` held in an `object` local. Handed to a parameter whose CLR type is `String[]` (an `@externTarget` binding, a function of another assembly such as `Lyric.Db`), the `List` was read as an array: an empty or garbage result, an `AccessViolationException`, or `SQL statement expects 8 parameter(s) ... but 905924832 were supplied`. The same literal written inline in the call, or bound with a `slice[String]` annotation, was always an array, which is why the fault depended on how the program was spelled. `ilverify` reports it (`StackUnexpected`, found `object`, expected `string[]`), but no self-test in its list had the shape.

The checker now records the checked type of the bracket literal(s) an unannotated `val`/`var`/`let` initializer yields (the literal itself, or the branches of an `if`/`match` that are literals) in `SymbolTable.listLiteralTypeSites`, the table `Lyric.Mono` already uses to bind a literal to a local of its checked type for generic element types (#7818). The backend that binds those sites (MSIL, native) therefore sees `{ val __lyric_ll_N: slice[String] = [...]; __lyric_ll_N }` and builds the `String[]` through the same `MArray` arm as the annotated form. The JVM binds only shape-required sites and is unaffected: it builds every literal as an `ArrayList` and converts at an array-typed boundary (`coerceArgTo`).

Regression test: `lyric-compiler/lyric/slice_literal_binding_array_self_test.l` (also in `scripts/ilverify-selfhosted.sh`'s list, so the IL is verified). See `docs/decisions/D-progress-1055-unannotated-slice-literal-binding-takes-checked-type.md` for the positions this does not cover.
