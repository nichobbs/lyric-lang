# B0012 retired: an alias two files bind to different packages is each file's own (#8690)

With plugin expansion, component glue, the weaver's A0047 lookup and the alias
rewriter's synthesised items reading each file's imports (D346), no pass picks one
package per alias from the union, so `Lyric.PackageMerge` no longer rejects an alias
two files bind to different packages. The union check was the census: the e2e
(`multi-file-package-merge-e2e.sh`) builds and runs a package whose two files bind `X`
to `Std.String` and `Std.Math`, and one using `X` as a type, constructor, pattern, call
and contract in a file that binds it to `Std.Core` beside a file that binds it to
`Std.String`, on dotnet, the JVM and native. A native-only gap found on the way, an
alias-qualified `X.newList()`, is #8913 and independent of this. `T0148` across files and
`T0123` stay.
