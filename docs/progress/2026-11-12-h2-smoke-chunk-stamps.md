# 2026-11-12 - dotnet h2 smoke: check 2 stamps arrivals without forking and logs the server's write times (#9009)

The `stdlib-builds` job failed twice on unrelated PRs with `h2 chunked response was not streamed incrementally` (first and second line 737 ms apart where the handler holds the second chunk 1.5 s). The cause was not reproduced: with a cold server, with eight busy loops competing for four cores, and with a warm-up request, the gap stayed at about 1470 ms in every local run. The check stamped each line by forking `date` after the read, so a starved runner could delay the first stamp by most of the gap. It now stamps with the bash builtin `$EPOCHREALTIME`, and `dotnet_h2_smoke.l` logs the server's own write times for the two chunks (`DOTNET-H2-SMOKE-STREAM first=.. second=..`), which the check prints when it fails, so the next failure says whether the server or the client side was late. The scheduler smoke passes 3 of 3 locally.
