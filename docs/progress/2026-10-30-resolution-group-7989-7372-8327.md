# Resolution group: missing-import calls, restored signature scope, fixtures as vals (#7989, #7372, #8327)

## Qualified calls through a missing package (#7989)

A qualified call whose qualifier names a package the file imports but no
dependency provides (a stale `bin/*.dll`, a package added since the dependency
was built) fell through to the bare-name lookup and typed against an unrelated
`run(String, List[String])` of another package. `typechecker_exprs.l` now
stops the fall-through (`importedPackageMissing`) and the qualified-name
resolution reports **T0215** at the reference, naming the package. Tests in
`typechecker_self_test.l`. Imports whose package is merely unused are not
diagnosed: the checker is given host-binding packages it cannot enumerate, so
an error at the import itself would be wrong for them (recorded in the PR).

## Restored signature types resolve in the producer's scope (#7372)

`symTableTryFindOne` now prefers, ahead of the last-registered fallback, a
declaration of a package reachable through the scope's imports' own imports.
A restored `Lib.show(u: in Uuid)` therefore binds `Uuid` to the host type
`Std.Uuid` re-exports, not to a consumer record named `Uuid`. Test in
`cross_package_generics_self_test.l`.

## Fixtures are module vals in every command (#8327)

`Lyric.Pipeline.fixturesAsModuleVals` rewrites `fixture` items to `val` items
in `pipePrepareForCheck`, as `Lyric.TestSynth` does for `lyric test`.

T0215 does not apply to `Std.*` packages: the toolchain supplies the standard
library whether or not a dependency or the caller loaded its sources.

## Found not to need a change, or deferred

- #8326: `lyric prove --features web lyric-lambda/tests/lambda_webbridge_tests.l`
  reports no T0042 on current main (after the name-resolution work in #8606),
  and the file is registered in `lyric-lambda`'s `[project.tests]` and passes
  under `lyric test --manifest lyric-lambda/lyric.toml`.
- #7203: the cross-package `.copy(field = v)` case (a record defined in a
  restored package, copied from another) builds and runs correctly in the
  `cross_package_generics_self_test.l` harness; a regression test was added.
  The original failure was seen only under the CLI's `--internal-perpackage-build`
  bundle, which that harness does not exercise.
- #7214: left open. docs/01 §3.1 keeps a `pub` signature naming a
  package-private type legal at the declaration and `lyric lint` warns (L007);
  making it an error reverses that design and needs a decision plus an audit
  of ecosystem signatures.
- JVM: running a consumer that calls a restored function whose signature names
  a re-exported extern type (`Std.Uuid.Uuid`) fails with `NoSuchMethodError`
  (the descriptor names the producer package as the type's owner). This is
  independent of #7372 (it fails without any shadowing consumer type) and is
  not fixed here.

## Review follow-ups

- The language server now passes each workspace package it resolves under its
  own name instead of one nameless merged package, so T0215 judges it like
  the build does (`lsp_self_test.l` caught this).
- `importedPackageMissing` also treats a package with a signature of that name
  in `sigs` as provided; the reachable-package set of `symTableTryFindOne` is
  built once per lookup.
