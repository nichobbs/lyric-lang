# Data grid (docs/65 §13.6, D154)

The third slice of phase U6 (after D152's first paint and D153's `Lazy`
subtrees): a grid for results too large to render or hold at once.

- **Widget.** `Widgets.dataGrid(spec, rows, onViewport, onSort)` and
  `gridRow`, with the new kinds `dataGrid`, `gridRow` and `gridCell`.
  - The runtime renders a header row and a scrolling body padded for the
    rows not rendered. It reports `viewport` (`"first,count"`) and `sort`
    events.
  - ARIA grid roles, row and column counts, and `aria-sort`; arrow-key row
    navigation, and Enter or Space activates a row.
  - `Ui.Html` renders the same markup for the first paint.
- **Events.** `Handler` gains `OnViewport` and `OnSort`. `Core.accepts`
  makes the session drop a viewport event whose data does not parse, or
  that asks for more than 1000 rows.
- **State.** The new pure `Ui.Grid` package: `Grid[Row]`, `RowQuery`,
  `RowPage`, `GridStep`; `empty`, `start`, `viewport`, `sortBy`,
  `filterBy`, `refresh`, `loaded`, `rowAt`. Queries are sequence-numbered,
  and only the latest answer applies.
- **Layers.** The `ui` preset lets logic, effects and views import
  `Ui.Grid` (`layers.l`; covered in `layers_self_test.l`).
- **Example.** `examples/ui-customers` lists 200 demo customers in a
  grid. `CustomerRepository.page(first, count, order, ascending)`
  replaces `all()`. The browser test sorts the grid and scrolls it to the
  end on both targets.
- **JVM fix (#7918).** A generic record's field instantiated over the
  record's own type parameters (`rows: List[T]`, `slice[T]`,
  `Map[String, T]`) now takes the receiver's arguments. `b.rows[i]` on a
  `Box[Int]` reads an `Int`; it used to read an erased `Object`, and
  arithmetic on it failed with J008. `JvmCaseField` records `argParamIdx`
  and the field's declared type (`declTy`).
  - A field typed as a generic record declared in another package
    (`grid: Grid[Customer]`) is stored as `Object`. Its class is now
    registered (`fieldcls:<class>#<field>`) and a read narrows to it, so
    later field and element reads resolve.
  - Covered in `erased_generic_arith_jvm_self_test.l` (same package) and
    `cross_package_generics_jvm_self_test.l` (a restored package).
- **Issues filed on the way:**
  - #7916: no diagnostic for a match arm after a wildcard arm.
  - #7917: a specialised generic body resolves a callee in the caller's
    scope.
- **D153 follow-ups (review of #7919).** A `Lazy` key duplicated for the
  first time in the current render is now rendered at each position
  instead of both reusing the one previous memo (`collectLazyKeys`, plus
  the keys met while resolving). The docs no longer say an unchanged lazy
  subtree "costs nothing". It is neither rendered nor diffed, but the
  session still walks it once per update.
