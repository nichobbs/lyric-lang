# 2026-11-13 - lyric-db, lyric-jobs, lyric-mq, lyric-otel and lyric-storage move from `incomplete` to `experimental`

Publish run 1835 could not publish these five (`F0052`, D552). Their unimplemented headline backends had already been removed from the public API or implemented (D552, docs/71 phases 2 and 4): db has real Npgsql/SQLite and JDBC kernels, mq has the in-process broker, jobs has `InProcessJobScheduler`, storage has the local filesystem backend, otel has recording and OTLP/HTTP export on both targets. Each `lyric.toml` `[package] stability`, each README `**Stability:**` line and the chapter 29 matrix now say `experimental`, so the ecosystem publish job releases them and `Lyric.Testing`'s workspace dependencies on Mq, Storage, Db and Jobs resolve from the registry.

`experimental` is a statement that the surface may still change, not that nothing is left: lyric-otel has no trace-context propagation (each span is its own trace root, see its README "Known limitations"); lyric-db's PostgreSQL path has no live server in CI; networked mq/jobs/storage backends live in `nichobbs/lyric-ecosystem`. `lyric-aws-secrets` stays `incomplete`. `scripts/ci/check-library-stability.sh` passes (29 libraries).
