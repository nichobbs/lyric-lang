# Explicit type-argument calls, generic interface conformance, Self joins (#8282, #7791, #7793)

- **#8282 explicit type-argument calls.** `checkExplicitTypeArgCall`
  (`typechecker_exprs.l`) checks `f[T](args)` against the signature the type
  arguments instantiate (`instantiateSigAt`): argument count T0042, argument
  types T0043. Before, nothing checked such a call, so `firstOf[Int](xs, 1, 3)`
  reached codegen as the T0120 internal error and `firstOf[Int](l, "s")` built.
  A call with a lambda or bracket-literal argument is checked for count only,
  since those take their type from the parameter. Native resolves a
  package-qualified callee (`Core.unwrapOr[Int](..)`): `llvm_codegen.l` EIndex
  arm and the reachability keys in `llvm_bridge.l`. Item 2 (overloaded generics)
  was fixed by #8622 (#8461). Item 3 (explicit type arguments on a record method,
  `s.pick[Int](4)`) is not done. `explicit_type_args_checked_self_test.l`.
- **#7791 interface generics.** The conformance check puts the interface's and
  the method's type parameters in scope, substitutes the impl's interface
  arguments, and renames an impl method's own type parameters to the interface
  method's. The JVM erases an interface method's own type parameters (and the
  interface's, in return position) in the abstract descriptor instead of naming a
  class `U` (`NoClassDefFoundError`). An impl of a generic interface is T0217
  (no backend lowers one), a wrong argument count T0216.
  `interface_method_generic_self_test.l` (dotnet, JVM).
- **#7793 Self joins.** Verified fixed on main for plain and generic targets, in
  impls and record bodies, on all three targets; `self_join_self_test.l` pins it.
  Native `impl[T]` for a generic target shipped in #8635.
