# 2026-11-17: follow-up to the host shapes (D445) from review

Review suggestions on #9203, carried into one cosmetic follow-up: `jvm_host_static_shapes` gains a host string passed for a host string parameter (`JKeyStore.getInstance(JKeyStore.getDefaultType())`) and an untyped array result returned as a slice (`toArray()`), both built with `--target jvm --verify-ir` and run; `hostArrayAsSlice` documents why `Object[]` is exposed as a slice and a typed array is not; `hostMethodOnTypeParam` documents that the active target's metadata resolver decides which root object class resolves. `compileToJar` (`lyric-compiler/jvm/bridge.l`) builds its middle-end options through the shared `jvmMiddleEndOptions` instead of a second hand-written `MiddleEndOptions` literal (the #9199 suggestion); every field the helper sets beyond the old literal equals the record default, and `interfaceTargets` is read only when `buildInterface` is set. No behaviour change. `jvm_host_chain_counted` adds the negative cases for the host chains the builder does not type (a chain on a `String` or boxed number result, an untyped array's `.length`): the JVM build finishes, the verifier reports nothing, the bodies stay counted. An untyped host array result is a slice only as a value: its `.length` stays counted until a member read on a `CvFromHost` slice is built.
