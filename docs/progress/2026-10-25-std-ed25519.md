# Std.Ed25519: pure-Lyric Ed25519 signatures (D248, plugins P7)

The first piece of plugin signing (D248 Decision 2). `lyric-stdlib/std/ed25519.l` adds `Std.Ed25519`:

- `ed25519PublicKey(seed)`, `ed25519Sign(seed, message)` and `ed25519Verify(publicKey, message, signature)`
  implement RFC 8032 Ed25519 over `Std.HashHost`'s SHA-512, with no other kernel, so one implementation runs on
  dotnet, the JVM and native.
- Signing takes the 32-byte seed and derives the public key itself on every call, so a caller cannot pair the seed
  with the wrong public key.
- The arithmetic follows TweetNaCl (16 limbs of 16 bits). The scalar multiplication is a ladder of masked swaps, so
  signing has no branches or table indices that depend on secret data.
- Verification is strict: it rejects a scalar `S` that is not below the group order, a public key whose `y` is not
  canonical or that encodes `x = 0` with its sign bit set, a small-order public key, and an `R` that is not the
  canonical encoding of the computed point (cofactorless check).

`lyric-stdlib/tests/ed25519_tests.l` runs the five RFC 8032 section 7.1 vectors (key derivation, signing and
verification), all 210 Wycheproof `ed25519_test.json` verification vectors, and explicit strict-check cases. The
Wycheproof "acceptable" cases are pinned to this implementation's policy: the eight small-order keys are rejected
and the 21 mixed-order keys accepted when the cofactorless equation holds. CI runs the suite on dotnet (the stdlib
runtime suites step), the JVM (beside `hash_tests.l`) and native (`scripts/ci/native-target-smoke-test.sh`).
`Std.Ed25519` joins `lyric.full.toml` as Tier 17 without `seed: current`, since the plugin signing commands in the
compiler will import it.
