# Build-system toolchain batch: every listed package is built, `prove` runs the target's rewrites, multi-file module docs (D262, #8357, #8311, #8246)

**#8357.** The JVM project build seeded its import-closure walk from the entry package, so a package of `[project.packages]` that nothing imports was never type-checked or emitted: its type error built green. `compileProjectToJarBundledWithRestored` now adds every sibling project package to the walk, as the dotnet build compiles every listed package. A package that does not apply to a target declares so with a file-level `@cfg(target = "...")` (docs/19 §4, docs/20 §4.1); `Grpc` and `Grpc.Aspects` are dotnet-only until the JVM kernel (Phase 6) exists, and the three `lyric-grpc` test modules that import them are gated the same way. `scripts/ci/project-all-packages.sh` runs `examples/jvm-unreached-package` on both targets: the JVM reports the unreached package's error and not the dotnet-only package's, dotnet reports both once the first is fixed, and the fixed project builds, runs and emits the package. The ecosystem JVM suites were run against the change (storage, resilience, mcp, health, generator-sdk, i18n, cache, feature-flags, mail, mq, auth, validation, web, forms, ui).

**#8311 (partial).** `Lyric.Pipeline.pipeExpandProfile(target)` is now the one place the three bridges' pre-check rewrite flags live (`runWireExpand`, `runStubbable`, `injectWeave`); the MSIL, JVM and native bridges call `pipeExpandAndRewriteFor` with their target name, and the check behind `lyric prove` (`Msil.Bridge.checkSourceTypesForFeatures`, `projectFrontEnd`) does too, so a native check no longer synthesises the `@stubbable` stubs the native build does not. A native check also erases by the host's `target_os`. `scripts/ci/prove-type-check.sh` gains `examples/prove-type-check/stubbable.l`: proved on dotnet and the JVM, rejected with the build's own T0020 on native, which `lyric build --target native` agrees with. Left open on the issue: the target-specific preparation of the standard library and the native shim and config-block diagnostics, which need each bridge's project front end split from its compile function.

**#8246.** `Lyric.PackageMerge` carries each contributing file's `//!` module docs into the merged unit, in file order with an empty `//!` line between files and per-line origins; a file turned off by its file-level `@cfg` contributes none. The packages the compiler discovers in its own trees (`mergeDiscoveredPackage`) now keep their docs too. `package_merge_self_test.l` pins the order, the separator, the origins, the gating and the parse of the merged unit; docs/19 §5 is updated to shipped.

**#7971 and #2444** are left open with a status comment and a plan each: the stdlib check cannot be skipped from a cache because its symbol tables lower the package that codegen consumes, and the target-gated bridge imports of `emitter.l` still need import annotations in the parser, which the retirement of the F# stage 0 no longer blocks.
