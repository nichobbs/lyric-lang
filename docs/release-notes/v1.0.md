# Lyric 1.0

Lyric 1.0 is the first release that carries a SemVer promise. This page says
what the promise covers, what it does not, and which library backends are
missing, before it lists what is new.

Every claim below cites the decision, issue or README it comes from. Items the
author could not check are marked **[unverified]**. No test run is claimed by
this document.

## What the 1.0 guarantee covers

- **`--target dotnet` is the reference channel.** SemVer applies to the
  language and to the `@stable` standard library (`docs/01` section 0.1, D040).
- **The stable stdlib surface** is the table in
  [`lyric-stdlib/STABILITY.md`](../../lyric-stdlib/STABILITY.md): every `pub`
  item in the listed modules is `@stable(since="1.0")` except the
  `@experimental` items named in its last column. `lyric public-api-diff`
  reports removing or changing a `@stable` symbol as breaking.
  - Four kernel-resident modules, `Std.Task`, `Std.HttpServer`, `Std.TcpHost`
    and `Std.Jvm`, are `@experimental` and outside the guarantee (D557, #8928).
  - `lyric public-api-diff` reads every package of a multi-package library, so
    the baseline for the 1.0 tag can be cut from `Lyric.Stdlib.dll` (#8927,
    #8955). See the upgrade notes: earlier versions of the command reported
    "no changes" for every pair of assemblies.

## What the 1.0 guarantee does not cover

1. **JVM.** `--target jvm` is supported and tested but has **no v1.0 SemVer
   guarantee**; breaking changes may land in minor releases, and it is versioned
   independently (G1, D-progress-620, `docs/01` section 0.1).
2. **Native and wasm32.** `--target native` (LLVM) and `--triple wasm32-wasi`
   (`--shape module`, `--shape component`) are outside the v1.0 SemVer guarantee
   and are versioned independently of the compiler (D548).
3. **Experimental UI and graphics libraries.** `lyric-ui`, `lyric-window`,
   `lyric-gpu`, `lyric-gpu-window`, `lyric-text`, `lyric-draw`, `lyric-game`,
   `lyric-unicode` and `lyric-access` are experimental; their APIs may change in
   any release (D548).
4. **Cross-package contracts are not enforced.** At 1.0 a restored library's
   `requires:` and `ensures:` clauses are **not enforced across the package
   boundary** for its consumers. Enforcement (docs/70 phase 6) follows 1.0
   (D549). Contracts are still checked inside the package that declares them.

## Ecosystem libraries: which backends are real

Libraries with unimplemented backends ship, labelled. An unimplemented backend
returns an explicit `NOT_IMPLEMENTED` error rather than failing silently, and
each library is versioned independently of the compiler (D549). The complete
per-target table is the
[library availability matrix](../../book/chapters/29-application-libraries.md#library-availability-matrix);
each library's README is the detailed source. The headline gaps, from that
matrix:

| Library | What is missing or does not exist |
|---|---|
| lyric-mq | Only the `inmemory` backend is real, and only on dotnet. RabbitMQ, Azure Service Bus, SQS and Kafka return `NOT_IMPLEMENTED` on dotnet. On the JVM there is no working backend (#6511). |
| lyric-storage | Local filesystem only. S3 and Azure Blob return `NOT_IMPLEMENTED` on both targets. |
| lyric-jobs | `hangfire` and `quartz` return `NOT_IMPLEMENTED` on dotnet. On the JVM the in-process schedulers and Quartz are real. |
| lyric-db | Npgsql and SQLite on dotnet. **No JVM backend exists** (#8932). |
| lyric-otel | OTLP/HTTP export is real on dotnet. On the JVM only recording is real; OTLP export is not implemented. |
| lyric-lambda | Experimental. HTTP and `Lambda.Stream` are not implemented. |
| lyric-aws-secrets | On `--target native`, `init()` returns an error until #7435. |
| lyric-aws-xray | On the JVM the `Tracing` aspect is broken (B-prime weaver gap). |
| lyric-ws | On the JVM, fragmented messages and keepalive pings are dotnet-only (Q-WS-001). |
| lyric-search | Implemented over HTTP but not usable against a live server (below). |

Stubbed backends are scheduled for removal from the public APIs, and SDK-bound
backends will move to separate packages (D552, `docs/71`).

Known defect at the time of writing:

- **lyric-search** is implemented over HTTP and tested on both targets against
  a fake `Std.HttpServer` engine for each backend (index, batch, search, suggest,
  exists, delete and error mapping, reading real response bodies). The
  `HttpResponse.bodyText` crash reported in #8940 does not reproduce on `main`.
  Neither backend has been driven against a real cluster in CI, so the package
  is `experimental`.

## Build profile

`--release` is a real profile (D555, closing #6263). Relative to `--debug` it:

- wraps integer overflow on `+ - *` and unary `-` instead of panicking, on every
  target (D163);
- does not check `ensures:` or the `requires:` of non-`pub` functions and methods
  (`--release-contracts` restores them) (D297, D307);
- defaults the native clang `-O` level to 2 instead of 0 (D-progress-913).

It does **not** optimise IL or bytecode on `--target dotnet` or `--target jvm`
(the runtime JIT optimises both builds alike), and no target emits debug
information yet. Both are tracked (#8946; docs/63 bands B1-B7). `--release` no
longer implies Native AOT: pass `--aot` (D132).

## Highlights since v0.7.12 (2026-10-31)

Decisions D296 to D551 were added after v0.7.12 (compared against the tree at
that tag). A selection; the decision log has the rest.

**Tooling and packaging**

- `--shape standalone` bundles a runtime into a directory for dotnet and the JVM
  (D297, #6262).
- Release builds follow a documented contract policy (above) (D297, D307).
- Tooling security: `lyric check` no longer runs `[[generators]]`
  host processes unless `--allow-generators` is passed, `lyric restore` runs
  `npm install --ignore-scripts` with a sandboxed export probe, and `[native]`
  linker arguments and dependency `subdir` fields are validated (D415).

**Language and checker (several are source-breaking; read before upgrading)**

- A protected type's fields can be reached only through its `entry`, `func`,
  invariant or `impl` members: `c.total` from outside is **T0221** (D305).
- A name a file sees only through a sibling file's import is **T0219**; imports
  are per file, and names reach a file only through whole imports and `pub use`
  re-exports (D300, D309, D311). `pub use P` re-exports a whole package.
- `in` makes a value record read-only; a `ref record` is a heap handle with
  reference identity on every target (D303, D415).
- A generic construction or call whose type arguments cannot be inferred is
  **T0224**; an expression with no type is **I0001**, an error (D335, D381,
  D385). `.count` on a slice is **T0228** (D358).
- A bare union case needs a visible name (**T0020** otherwise) and a bare enum
  case that is ambiguous is **T0222** (D312, D328).
- `@proof_required` packages check fixed-width integer overflow by default;
  `@proof_required(unbounded_arithmetic)` opts out (D415). The verifier now
  fails closed on calls it cannot order (D546, **V0033**).
- `ULong` and `UInt` work on `--target native` (D308).

**Native target** (outside the 1.0 guarantee, see above)

- The async scheduler uses per-thread work-stealing deques (D403), spawn
  arguments must be sendable (`Send` marker, **T0225**, **T0226**, D404), an I/O
  reactor keeps blocked sockets from occupying scheduler threads (D405), and the
  default is multi-threaded (D404 item 8).

**Experimental UI and graphics libraries**

- Unicode 16, line and word breaking, bidirectional layout and dictionary
  segmentation for Thai, Lao, Khmer and Myanmar (D371, D372, D411, D412, D414),
  native text input editing (D413), and accessibility through AccessKit on
  Linux, macOS and Windows (D376).

**Compiler internals toward 1.x**

- The resolver, the typed IR and checked package interfaces (docs/70, D267 and
  D300 onward) are in progress; cross-package contracts depend on them and are
  therefore after 1.0 (D549).

## Upgrade notes

- Programs that relied on `--release` selecting Native AOT must pass `--aot`
  (`F0042` reports the removed `[build] kind = "aot"`).
- Expect new compile errors from the checker items marked above in code that
  previously compiled; each diagnostic names the fix.
- `lyric public-api-diff` now compares per-package contracts in-process and
  reads multi-package libraries. In earlier releases it reported "no changes" for
  every pair of assemblies, including a removed `@stable` function (#8927). Re-run
  any CI gate that relied on it: it can now fail where it used to pass.

  the project lead's D549 designates as the source, and were cross-read, not
  executed.
- Whether #8940 (lyric-search; the crash it reports does not reproduce, so it
  can close once a note is left on the issue) and #8946 (no IL or bytecode
  optimisation under `--release`) are still open at the tag.
- The library matrix was reconciled against `main` on 2026-11-10 and has not been re-checked since; the matrix and the READMEs are being reworked under `docs/71`, so re-read both before publishing.
- That the highlights list is complete: it is a selection from roughly 120
  decision entries and 170 progress entries added since v0.7.12.
